# Proof and evidence bank

What OS A.I can actually put behind a claim. **With no results data, proof has to come from
mechanism, process and specificity** — which, done well, is more persuasive to a burned buyer than
another vendor's numbers.

## Tier A — hard, checkable facts

| Proof | Use it for |
|---|---|
| **ABN 75 527 278 804**, registered Australian business, Werribee VIC | "Is this a real company?" |
| Published Terms, Privacy, Cookie, Acceptable Use, Affiliate and Refund policies | Legitimacy, due diligence |
| Australian-owned and operated | Local-market credibility with an AU ICP |
| Contactable: phone, email, registered address | Trust. Many competitors in this category are anonymous |
| Five named team members with defined roles | Not a faceless reseller |

## Tier B — mechanism proof

The strongest material available. **Specificity is the proof.**

| Proof | Use it for |
|---|---|
| **The ten-step onboarding SOP with named owners** and a QA gate | Pillar 3. The single best proof asset OS A.I has |
| **The kickoff call is prepared against the client's own top three problems** | Not a template. Genuinely differentiating detail |
| **The five-department automation library** — named, built workflows across marketing, sales, ops, partners and admin | Delivery capability. These exist, they are not a roadmap |
| **The named replacement map** — Mailchimp, Calendly, ClickFunnels, Zapier, Intercom, Wix, Kajabi | Pillar 2. Concrete and checkable |
| **Twelve capability modules**, specified in detail | Depth. Survives technical interrogation |
| Draft → staging → production with version control and rollback for AI agents | Agency-founder credibility. This is a real engineering practice |
| DNC compliance checks built into outbound voice | Compliance maturity |
| Sentiment detection with escalation to a human | Answers "what if the AI mishandles someone?" |

## Tier C — approved published claims

C1–C5 in the [claims register](claims-register.md). Usable per D2, **within the stated bounds**. C6 is
recorded but **not approved for reuse**.

## Tier D — does not exist

Results, case studies, testimonials, client counts, revenue, retention, uptime, certifications,
awards. See [what we cannot claim](what-we-cannot-claim.md).

## Proof-by-objection

| Objection | Reach for |
|---|---|
| "Will this actually get set up?" | The ten-step SOP with named owners. The QA gate |
| "Is this just another chatbot?" | Agent Studio: routing, multi-bot, knowledge bases, staging |
| "What if it says something wrong?" | Trained on your material · human-approval mode · sentiment escalation · staging before production |
| "Are you a real company?" | ABN, address, phone, published policies |
| "Can it handle my industry?" | Kickoff prepared against your top three problems · knowledge-base training · web-crawler training |
| "Do you have proof it works?" | **Be honest.** "We're early. Here's exactly how it works — judge it on the mechanism." Then Tier B |
| "Why not just use Zapier?" | Silent breakage · maintenance burden · no system knows the whole customer |

## The rule

**Never reach for Tier C when Tier B will do.** A specific mechanism is more persuasive to this
buyer than an unsubstantiated superlative — and it is the thing a competitor cannot copy by writing
a better headline.
